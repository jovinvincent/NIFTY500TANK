Date: 2026-11-22 · **Rev 5.1** — verified-source remediation plan (NSE/Yahoo/Tickertape endpoints probed live); 2021 P/E break re-attributed to NSE's own data; equal-weight integrity check added; legacy-module findings removed as out of scope.

## VERDICT
The market-data pipeline is partially genuine and the UI is polished, but three headline claims do not survive contact with the code:
1. **The data you see by default is synthetic**, and the app re-labels it "VERIFIED EOD".
2. **The "multi-decade P/E percentile" compares across a real basis break in NSE's own published P/E at 2021-03-31** — official files show Nifty 500 43.33 → 35.89 (−17.2%), and the break differs per universe (Midcap 150 −44.8%, Next 50 +11.3%). The app neither labels nor normalises it.
3. **The Peak Sniper has no demonstrated edge.** Its "sell" calls were followed by *above-baseline* returns (+10.95% vs +6.52% over 120 days).

The stock master and the VIX series are essentially sound; the MMI feed has a small but real look-ahead defect; breadth coverage is broken before 2020.

Everything below is verified with computed numbers, not inspection alone.

### What each source fixes
- **Tank history** — compute the bins yourself: per stock, distance from 52-week high, aggregated over a *dated* constituent list from bhavcopy. One source, same definition as the app, zero synthesis.
- **Breadth** — count advancers/decliners from the same bhavcopy; store `coverage = available / constituents` per row. This removes the 59→100% drift (H1) instead of masking it.
- **VIX 2008–2016** — India VIX is in the same `ind_close_all` file; backfill to inception (~2008) instead of declaring `vixDates: 1978` with no data (C3).
- **P/E** — switch to the single official series. The 2021 step remains, but it becomes a documented NSE basis change rather than an unexplained jump; if needed, rebuild both bases from constituent EPS.
- **MMI** — snapshot `/mmi/now` daily around 15:45 IST, store the raw payload with fetch timestamp, reject any row whose date ≠ snapshot date (kills the 14 next-day duplicates), dedupe by date. History accumulates from deploy; `lastDay/Week/Month/Year` gives validation anchors.

### Pipeline (daily, idempotent)
1. Fetch `ind_close_all`, bhavcopy, constituent snapshot; keep raw files with URL, fetch time and SHA-256.
2. Validate: expected indices present, rows > threshold, price > 0, P/E 5–100, VIX 8–90, no weekend dates.
3. Build derived assets; write a manifest per asset: `{source_url, fetched_at, rows, first_date, last_date, sha256, coverage}`.
4. App emits `VERIFIED_EOD` **only** when the manifest hash matches and coverage ≥ 99% — the badge becomes evidence-based, not hardcoded.

### Accuracy gates (fail the build)
- Trading-calendar continuity: no weekends, no gap > 3 sessions unexplained.
- Cross-source check: index close from `ind_close_all` vs Yahoo within 0.1%.
- `bins` sum == `activeCount`; `dailyDelta` == level difference (already true today).
- Percentiles computed within one basis regime only.
- MMI: one row per date, mood band consistent with value.
- VIX: no identical values on non-adjacent dates (catches the copied Saturday row).

### What no data source can fix
- **No public dataset predicts tops and bottoms.** MMI, VIX and breadth are regime descriptors. "Accurate forecasting" can only be demonstrated by walk-forward, out-of-sample tests — not by better provenance. The current peak signal shows *negative* skill (C10).
- True point-in-time Nifty 500 membership before ~2015 is not freely available; apply the current list backwards and label it as such (H2).
- **Licensing**: NSE data is for personal use; redistributing raw NSE files inside a public GitHub repo is a terms-of-use problem. Keep the raw archive outside the public repo or ship only derived series with attribution.

## EQUAL-WEIGHT INTEGRITY CHECK (added Rev 5.1)

**The live measurement engine is genuinely equal-weight — no market-cap term exists anywhere in the tank path:**

| Component | Evidence |
|---|---|
| Per-stock score | `(price − low52W) / (high52W − low52W) × 100` — position in its own 52-week range; no cap term (`TankModels.kt:508-515`) |
| Main Tank level | Σ per-stock overflow above the valve ÷ (eligible count × max) — a plain average across constituents (`TankModels.kt:543-557`) |
| Bins / holes / bands | 20 count buckets of 5 points; every hole level, band, capitulation % and euphoria % = count ÷ eligible n (`DeadlyComboModels.kt:307-382`) |
| Median P/E | Equal-weight median of constituent P/Es (`TankModels.kt:566-574`) |
| Eligibility | Uniform: ≥200 trading days of 52-week window, else excluded — same rule for every stock (`TankModels.kt:506-512`) |

The only `market_cap_basic` reference in the codebase is the TradingView scanner's sort used to pull a broad price list, which is then matched against the official constituent list (`AdvanceDeclineManager.kt:650`) — weights are never used in measurement. Note the universe *membership* itself is NSE's cap-based selection; the app measures it equal-weight, which is the stated philosophy.

**Where cap-weighted data leaks in (4 places):**

1. **Valuation pillar — primary P/E is cap-weighted.** `primaryAbsolutePe = indexPe ?: medianPe` (`DeadlyComboModels.kt:100-102`, applied `:1077-1103`): official NSE index P/E (free-float cap-weighted aggregate) is primary; the equal-weight median is fallback only. Documented in code, but the "unbiased absolute P/E" is cap-weighted whenever official data exists — and it carries the 2021-03-31 basis break.
2. **Pre-2016 "equal-weight" history is a cap-weighted proxy.** Bins are synthesized via `reconstructBinsFromSummaryMoments` (`TankModels.kt:897/923/934`) from index summary moments, and A/D is `50 + dailyDelta×8` from the cap-weighted Nifty 50 (`DeadlyComboModels.kt:947`). The 1995→2016 slice of the "equal-weight truth" chart is synthetic breadth derived from a cap-weighted index.
3. **VIX and MMI macro factors are cap-weighted index derivatives** — inherent to those feeds. Acceptable as regime overlays; they are not breadth.
4. **Edge benchmark is cap-weighted.** Forward returns are measured against Nifty 500 index levels. An equal-weight signal should also be tested against an equal-weight baseline (mean/median constituent return); the cap-weighted benchmark can mask or manufacture "edge".

**Fix options:** promote the median-P/E percentile to primary (or show both, labelled) — needs per-stock P/E history, which the remediation pipeline can build from bhavcopy + results; exclude pre-2016 from equal-weight edge claims or rebuild it from NSE archives once backfilled; add an equal-weight benchmark column to the sniper validation.

## CRITICAL BUGS

### C1. Synthetic data is displayed as "VERIFIED EOD"
`nifty500_tank_history.json` self-declares:
```
"dataQuality": "ILLUSTRATIVE_FALLBACK", "isIllustrative": true
```
`TankRepository.kt:237-244` (no-cache path) and `:207-215` (cache path) publish:
```
dataQuality = DataQuality.VERIFIED_EOD, isIllustrative = false
```
`DashboardScreen.kt:339` renders the badge from that value → **"VERIFIED EOD"** on the same screen where history integrity still says ILLUSTRATIVE. The honest header is overridden by the UI layer. This also invalidates `DeadlyComboModels.kt:474` ("Verified across 2,617 days") — those 2,617 days are the illustrative series.
**Fix**: propagate the asset header; never emit VERIFIED_EOD without a live ≥450-stock session; badge the whole app "ILLUSTRATIVE" otherwise.

### C2. Official NSE basis break at 2021-03-31, used without disclosure
NSE's own daily files (fetched and diffed during this audit):
```
30-03-2021  ind_close_all_30032021.csv   Nifty 500  P/E 43.33  P/B 3.99
31-03-2021  ind_close_all_31032021.csv   Nifty 500  P/E 35.89  P/B 3.96
```
Every value on both sides matches the app's series **exactly** — so this is not an invented or vendor-stitched number. It is a genuine discontinuity in NSE's published P/E, consistent with the 31-March index reconstitution / earnings-basis change. The asset metadata even records it (`consolidatedTransitionDate: 2021-03-31`), but the percentile engine and UI ignore it, and the size of the break differs by universe (official values):

| Universe | P/E 03-30 → 03-31 | P/B same day |
|---|---|---|
| Nifty 500 | 43.33 → 35.89 (**−17.2%**) | 3.99 → 3.96 (−0.8%) |
| Nifty 50 | 40.43 → 33.20 (**−17.9%**) | 4.21 → 4.20 (−0.2%) |
| Next 50 | 38.23 → 42.54 (**+11.3%**) | 4.53 → 4.55 (+0.4%) |
| Midcap 150 | 73.56 → 40.58 (**−44.8%**) | 3.38 → 3.24 (−4.1%) |
| Smallcap 250 | 42.54 → 43.30 (+1.8%) | 2.99 → 2.91 (−2.7%) |

`DeadlyComboModels.kt:1096-1103` calls the 2021+ slice a "Cons." percentile but compares the current P/E against a "20Y" band that spans both bases. Current Nifty 500 P/E 22.50 reads as **46.4th percentile on the mixed 2007+ window vs 58.8th on the clean 1999+ window** (the code's `benchmarkWindowStart = "2007-01-01"`); the same absolute P/E lands at the **67.7th percentile pre-break-only vs 23.8th post-break-only** — a 44 pp swing caused solely by the basis change. Across 700 of 4,928 dates (**14.2%**, full-sample ranks) the two windows put the same P/E on opposite sides of the 50th percentile.
Date parity compounds it: the P/E file runs to **2026-11-20** while the tank ends **2026-11-13** and the index **2026-11-12** — the "current" regime blends a week-old breadth reading with a fresh valuation.
**Fix**: do **not** ratio-adjust (that would corrupt genuine history). Either compute percentiles within one basis regime and label it, show a dual-basis chart with the break marked, or rebuild standalone and consolidated series separately. Align the series end-dates while doing it.

### C3. Pre-2016 VIX hours claimed, never shipped
`pre2016_manifest.json` declares `"vixDates": 1978`. `pre2016_macro_overlays.json.gz` contains only `{date, ad}` — **no VIX array at all**. Any pre-2016 VIX factor is silently empty (`pre2016VixSessionCount = 0`), which also lowers the sniper's denominator and therefore its pass mark.
**Fix**: remove the manifest claim or ship the series; never shrink the denominator silently — show N/A per factor.

### C4. Look-ahead disguised as its opposite
`DeadlyComboModels.kt:958-975`:
```
// Only fold immediate live macro updates (<= 7 calendar days after lastHistDate)
// so historical point-in-time reports never suffer look-ahead bias
for (k in sortedMacroDates) { if (k > lastHistDate) { if (calendarDaysBetween(lastHistDate,k) > 7L) break; ... } }
```
It folds macro data from **up to 7 days after** the report date into the "current" reading. Recomputation: flips Peak rule 7 on **491 days** and rule 8 on **564 days** — a quarter to a fifth of the sample.
**Fix**: clamp to `k <= lastHistDate`.

### C5. The backtest number is a literal
`DailyRecommendationSummaryScreen.kt:462`:
```
.let { if (it.isNaN()) 2.4 else it }   // → "Backtested alpha: +2.4% vs blind SIPs"
```
When no positive alphas exist, the UI prints a hardcoded +2.4%. Separately, 17 `HistoricalComboEpisode(...)` literals (DeadlyComboModels.kt:1903-2338) — including the COVID-2020 bottom — are hand-typed constants (VIX 71.9, MMI 4.5, fwd-6M +40.5%) rendered as computed analytics; pre-2016 episodes pick `maxByOrNull{tankLevel}` inside hand-drawn windows and stamp the sniper trigger on that exact date.
**Fix**: delete the fallback; either compute episodes or label them "editorial commentary".

## HIGH

### H1. Breadth coverage drifts 59%→100%, unnormalised
`advance_decline_historical.json` carries 8 universes. Nifty 500 totals average **439/500 (87.8%)**, min **295/500** (2016-04-01); 918 of 2,617 days (all pre-2020) are partial-universe. The shortfall is systems-wide, not N500-specific: **Nifty 50 is also below 50 names on 918 days** (44–49 names), Nifty1000 is below 1,000 on 102 days (min 484). Tank asset simultaneously claims `constituentCoverage: 1.0`. A breadth ratio computed on 295 names is not comparable to one on 500.
**Fix**: store `coverage` per row and either backfill history or percentile-normalise within coverage regime.

### H2. Survivorship and look-ahead are NOT eliminated (claim is false)
Constituents are one static, undated snapshot applied backwards to 1995. Only Nifty 50 and Next 50 are marked point-in-time (`isPitUniverse`, :1073); the UI presents all five as PIT. Nifty 500 coverage ramps 103 names (2007) → 473 (2026) — a listing ramp, not membership. 20 current constituents have no valuation anchor.
**Fix**: ship dated constituent snapshots; until then the honest label is "current constituents applied historically".

### H3. "From Jan 1995" is 160 blank rows + 721 reconstructed
5,261 pre-2016 rows: 160 `INCOMPLETE_COLD_START` (all zeros, 1995-01-02→1995-08-24), 721 `RECONSTRUCTED_HISTORICAL` (ends 1998-07-31), 4,380 untagged. Effective real breadth starts 1998-08.
**Fix**: start charts at 1998-08 or shade the reconstructed band.

### H4. MMI feed duplicates carry the *next session's* value — a small look-ahead
2,633 rows across 2,619 dates, **14 duplicate dates, all with conflicting values**, and in every case the duplicate's `source_id` is the **following session** — e.g. 2026-01-14 holds both `source_id 20260114 / 62.45 "Greed"` and `source_id 20260115 / 25.0 "Extreme Fear"`; 2026-01-23 also holds 20260126. Last-wins parsing therefore stamps **next-day MMI onto the prior date** on 14 days. Also: 2 weekend rows (2025-02-01, 2026-02-01), 12 records with a blank mood, and an A/D placeholder row 2026-01-15 (adv=0, dec=0, unc=500).
Sanity checks that pass: value range 4.5–82.4, no zeros, mood bands clean (Extreme Fear ≤25.0, Fear 25.1–45, Neutral 45–55, Greed 55–75, Extreme Greed ≥75); corr(MMI, VIX) = **−0.57** (correct sign and plausible strength); corr(MMI, breadth) = only **+0.27**, so "MMI" and "A/D" are not close substitutes — the 9-factor vote treats them as independent when they barely overlap.
**Fix**: de-duplicate by `source_id == trading date` at ingest; reject non-trading dates; reject all-unc rows.

### H5. VIX calendar: holes and a fabricated Saturday
2,605 dates 2016-04-01→2026-11-13. Distribution is credible — mean 16.37, median 14.91, max 83.61 (COVID), no zeros/negatives, corr(daily N500 return, ΔVIX) = **−0.608** — so the series is genuine where present. But **167 weekdays are missing** (some are exchange holidays; 17 of them are tank sessions with no VIX), the longest unchanged run is only 2 days (no stale padding), yet **Saturday 2026-10-31 carries 14.85 — an exact copy of 2026-10-20**. Tank/AD/index/MMI all share the hole 2016-08-12. `index_historical` stops at 2026-11-12 while the tank reaches 2026-11-13 and the P/E file 2026-11-20, and every index date is stored twice (ISO + "01-Apr-2016", 5,232 keys for 2,616 days).
**Fix**: single canonical trading calendar; forward-fill only within N sessions and mark filled rows; drop the Saturday row.

### H6. Trough factor 8 is a tautology
`DeadlyComboModels.kt:731`: `isTriggered = maxVix15 >= 15.0 && curVix <= maxVix15`. `curVix` is the last element of the same 15-day window, so `curVix <= maxVix15` is **always true**. Factor 8 reduces to "VIX max ≥ 15" and fires **67.8%** of days. Other fire rates: P7 48.1%, P9 53.5%, B4 47.3%.
**Fix**: require a real stabilisation condition (e.g. curVix ≤ 0.9× maxVix15 and maxVix15 ≥ 25).

### H7. The "9 factors" are not independent
Unweighted vote counter, 1 vote each (:615). P4/P5/P6 all require `h75Max15d ≥ 38.0`, so three of nine votes are gated on the same condition; all nine derive from one histogram of the same 500 stocks. No calibration, no weights, no cross-validation.
**Fix**: report factor correlation; cap or weight the correlated trio.

### H8. "≥8/9 confluence" contradicts the engine
`DeadlyComboModels.kt:151` and `:1860` advertise "Peak Sniper ≥ 8/9". `proportionalCriticalMin(9) = 7` (:276). In the recomputed sample: 14 of 22 calls fired at 7/9, one at 6/9. A 7/9 threshold on 9 correlated votes is not a sniper.
**Fix**: align copy to code or raise the gate and show the hit rate.

### H9. The project cannot be built from a clean clone
No `gradlew`, `gradlew.bat`, or `gradle/wrapper/*` anywhere. Plus: `kotlinx.coroutines.tasks.await` imported in `RemoteTankDataSource.kt:13` and `FirebaseAuthFirestoreManager.kt:10` with no `kotlinx-coroutines-play-services` dependency; debug signing points at a gitignored `${rootDir}/debug.keystore`; release keystore absent with null passwords; probable Java 11 vs Kotlin jvmTarget mismatch; `test_chaq.gradle.kts` is unreferenced Chaquopy junk; root `cleanRootJunk` task deletes root `.txt/.py`.
**Fix**: commit the wrapper (`gradle wrapper`), add the coroutines-play-services artifact, generate a debug keystore or drop the signing config.

### H10. Firebase "inter-day vault" can never run
No `google-services.json`, no Google Services plugin, `FirebaseApp` never initialised — so `FirebaseAuthFirestoreManager` and the Firestore vault are structurally dead. Live quotes come from a **TradingView scanner**, not NSE.

### H11. Device-side scraping + over-broad exposure
NSE calls spoof a desktop UA/Referer and replay harvested session cookies; goodreturns is already Cloudflare-blocked (`page.html` is the saved block page); Tickertape/Yahoo/stra/qsif also scraped from the device. `allowBackup=true` with empty backup rules ships the Room portfolio DB to cloud backup; FileProvider exposes `external-path "."`; 55 screenshots (28.76 MB) with real portfolio values (₹20.28 L invested / ₹22.52 L value / XIRR) are public in the repo.
**Fix**: move scraping server-side, set `allowBackup=false`, narrow the FileProvider path, strip screenshots.

### H12. A/D breadth is fabricated from the tank's own price delta when AD is missing
`DeadlyComboModels.kt:947`:
```
else -> (50.0 + activeHist[i].dailyDelta * 8.0).coerceIn(10.0, 90.0)
```
Where real A/D is absent, "breadth" is synthesized from `dailyDelta` — which is itself a function of the price histogram the p1–p5 rules read. Any sniper vote that mixes real and synthesized A/D is partially comparing price to price. Pre-2016, Nifty 500 A/D is additionally a duplicate of Nifty 50 A/D for the first 12 sessions (identical values to 1995-09-08, first divergence 1995-09-11).
**Fix**: return N/A for missing A/D (and let the denominator shrink visibly), never interpolate breadth from price.

### H13. VIX carry is unbounded and defaults to a magic constant
`IndiaVixManager.kt:262,277,286`: nearest-date lookup with **no maximum distance** — a date with no VIX data receives the last known VIX however far back it is, or the literal `14.54` ("current benchmark default") when the map is empty. Combined with C3 (no pre-2016 VIX shipped), pre-2016 VIX-based factors can be reading a stale or fabricated constant. Also present in the shipped data: a fabricated Saturday row 2026-10-31 whose value (14.85) is an exact copy of 2026-10-20, and 17 missing genuine weekday sessions.
**Fix**: cap carry at ~5 sessions, mark carried values, delete the 14.54 default, validate the calendar.

### H14. MMI is 40% VIX by construction, so P7 and P8 double-count
`MarketMoodIndexEngine.kt:80-82`: `WEIGHT_TMMI = 0.30, WEIGHT_GMMI = 0.30, WEIGHT_VIX = 0.40`. The composite MMI that Peak rule 7 reads already contains a 40% weight on a VIX-derived score — the same input rule 8 votes on. Two of nine "independent" factors share ~40% of their signal (and TMMI/GMMI are themselves correlated third-party sentiment composites).
**Fix**: either exclude the VIX component when rule 8 is active, or document the overlap and drop the "9 independent factors" framing.

### H15. MMI docstring contradicts the code
